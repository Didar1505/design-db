# Практическое задание: `INSTEAD OF DELETE` и Soft Delete

Используя таблицу `cards`, представление `active_cards` и принцип **Soft Delete**, реализуйте удаление карты через `VIEW` без физического удаления записи.

## Задание 1. Перехват операции `DELETE`

Создайте представление:

```text
active_cards
```

которое показывает только активные карты:

```text
deleted = 0
```

Затем создайте триггер:

```text
soft_delete_card
```

Триггер должен:

- срабатывать при попытке выполнить `DELETE` через `active_cards`;
- использовать `INSTEAD OF DELETE`;
- не удалять запись из таблицы `cards`;
- найти карту с помощью `OLD.id`;
- установить для неё `deleted = 1`.

После создания триггера выполните:

```sql
DELETE FROM active_cards
WHERE id = 2;
```

Проверьте результат:

```sql
SELECT * FROM cards;

SELECT * FROM active_cards;
```

Карта должна остаться в `cards`, но исчезнуть из `active_cards`.

## Задание 2. Проверка Soft Delete

Выберите другую активную карту и удалите её через:

```sql
DELETE FROM active_cards
WHERE id = ...;
```

После этого проверьте:

1. Существует ли запись в таблице `cards`.
2. Какое значение теперь находится в `deleted`.
3. Отображается ли карта в `active_cards`.
4. Сохранились ли связанные с картой записи в `transactions`.

Объясните цепочку выполнения:

```text
DELETE FROM active_cards
        ↓
INSTEAD OF DELETE
        ↓
TRIGGER
        ↓
UPDATE cards
SET deleted = 1
        ↓
Запись физически не удаляется
```

## Задание 3. `WHEN` при изменении баланса

Создайте триггер, который срабатывает после изменения `balance` карты, **только если новый баланс стал отрицательным**.

Используйте условие:

```sql
WHEN NEW.balance < 0
```

Если условие истинно, триггер должен добавить информацию о карте в отдельную таблицу:

```sql
CREATE TABLE balance_warnings (
    id INTEGER PRIMARY KEY,
    card_id INTEGER,
    balance NUMERIC,
    created_at NUMERIC DEFAULT CURRENT_TIMESTAMP
);
```

Проверьте триггер двумя операциями:

- измените баланс карты на положительное значение;
- измените баланс карты на отрицательное значение.

Определите, в каком случае появилась запись в `balance_warnings`.

## Задание 4. `WHEN` при Soft Delete

Измените или создайте триггер `INSTEAD OF DELETE` для представления `active_cards`.

Триггер должен выполнять Soft Delete **только для карты с нулевым балансом**.

Используйте условие:

```sql
WHEN OLD.balance = 0
```

Если условие выполняется, триггер должен:

```text
deleted = 1
```

Проверьте работу триггера:

1. Попробуйте удалить через `active_cards` карту с `balance = 0`.
2. Попробуйте удалить карту с `balance > 0`.
3. Проверьте таблицу `cards`.
4. Определите, в каком случае значение `deleted` изменилось.

> `WHEN` позволяет задать условие выполнения триггера. Если выражение после `WHEN` истинно, тело триггера выполняется. Если условие ложно, команды внутри триггера не выполняются.
