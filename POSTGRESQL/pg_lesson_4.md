# Часть I. Теоретический материал

## 2. Что такое хранимая процедура?

Хранимая процедура — именованный блок SQL- и PL/pgSQL-команд, который сохраняется в базе данных и вызывается для выполнения определённых действий.

Например, в интернет-магазине постоянно выполняются операции:

- Добавление нового товара.
- Изменение цены.
- Пополнение склада.
- Продажа товара и уменьшение остатков.
- Удаление товара.

Вместо того чтобы каждый раз писать несколько SQL-команд, можно создать процедуру.

## 3. Чем процедура отличается от функции?

На предыдущем занятии мы создавали функции:

```
SELECT calculate_discount(5000, 10);
```

Функция возвращала вычисленную цену.

Процедуру вызывают иначе:

```
CALL update_product_price(1, 70000);
```

Она может изменить цену товара непосредственно в таблице.

| Функция                                  | Процедура                                              |
| ---------------------------------------- | ------------------------------------------------------ |
| `CREATE FUNCTION`                        | `CREATE PROCEDURE`                                     |
| Вызывается через `SELECT`                | Вызывается через `CALL`                                |
| Объявляет тип результата через `RETURNS` | Не использует `RETURNS`                                |
| Возвращает результат через `RETURN`      | Может передавать значения через `OUT`/`INOUT`          |
| Может использоваться в SQL-выражениях    | Не используется как выражение в `SELECT`               |
| Не управляет транзакциями                | При определённых условиях может управлять транзакциями |

Важно: функции PostgreSQL тоже могут изменять таблицы. Основное различие не в том, что функция только читает, а процедура изменяет данные, а в способе вызова, возврате результатов и возможностях управления транзакциями.

## 4. Синтаксис CREATE PROCEDURE

```
CREATE PROCEDURE procedure_name(parameters)
LANGUAGE plpgsql
AS $$
DECLARE
    -- Переменные
BEGIN
    -- SQL-команды
END;
$$;
```

Вызов процедуры:

```
CALL procedure_name(arguments);
```

Обратите внимание: в отличие от функции, здесь нет `RETURNS INTEGER` или `RETURNS TEXT`.

## 5. Первая процедура

Создадим процедуру, которая выводит приветствие:

```
CREATE PROCEDURE say_hello()
LANGUAGE plpgsql
AS $$
BEGIN
    RAISE NOTICE 'Привет, PostgreSQL!';
END;
$$;
```

Вызов:

```
CALL say_hello();
```

Результат в сообщениях PostgreSQL:

```
NOTICE: Привет, PostgreSQL!
```

`RAISE NOTICE` выводит информационное сообщение, но не возвращает значение как функция.

### Процедура с параметром

```
CREATE PROCEDURE greet_user(username TEXT)
LANGUAGE plpgsql
AS $$
BEGIN
    RAISE NOTICE 'Здравствуйте, %!', username;
END;
$$;
```

```
CALL greet_user('Александр');
CALL greet_user('Мария');
```

Вопрос студентам: что произойдёт, если вызвать `CALL greet_user();` без аргумента?

# Часть II. Процедуры для работы с таблицами

## 6. Подготовка таблицы

Продолжаем использовать таблицу `products` из предыдущего занятия.

```
SELECT * FROM products;
```

Если таблица сохранилась, повторно создавать её не нужно.

## 7. Добавление товара через процедуру

```
CREATE PROCEDURE add_product(
    p_name VARCHAR,
    p_price NUMERIC,
    p_quantity INTEGER
)
LANGUAGE plpgsql
AS $$
BEGIN
    INSERT INTO products (name, price, quantity)
    VALUES (p_name, p_price, p_quantity);
END;
$$;
```

Вызов:

```
CALL add_product('Веб-камера', 4500, 10);
```

Проверка:

```
SELECT * FROM products;
```

Теперь студенты видят, что `CALL` выполняет действие, изменяющее данные в базе.

## 8. Изменение цены товара

```
CREATE PROCEDURE update_product_price(
    p_id INTEGER,
    p_new_price NUMERIC
)
LANGUAGE plpgsql
AS $$
BEGIN
    UPDATE products
    SET price = p_new_price
    WHERE id = p_id;
END;
$$;
```

Вызов:

```
CALL update_product_price(1, 70000);
```

Проверка:

```
SELECT * FROM products WHERE id = 1;
```

Вопрос: что произойдёт, если передать идентификатор несуществующего товара?

Ответ: процедура выполнится без ошибки, но не изменит ни одной строки.

## 9. Удаление товара

```
CREATE PROCEDURE delete_product(p_id INTEGER)
LANGUAGE plpgsql
AS $$
BEGIN
    DELETE FROM products
    WHERE id = p_id;
END;
$$;
```

```
CALL delete_product(7);
```

Здесь важно обсудить, почему удаление по `id` безопаснее, чем удаление без условия `WHERE`.

# Часть III. Условия и проверки в процедурах

## 10. Проверка цены перед изменением

Усовершенствуем процедуру изменения цены.

```
CREATE OR REPLACE PROCEDURE update_product_price(
    p_id INTEGER,
    p_new_price NUMERIC
)
LANGUAGE plpgsql
AS $$
BEGIN
    IF p_new_price < 0 OR p_new_price IS NULL THEN
        RAISE NOTICE 'Некорректная цена';
    ELSE
        UPDATE products
        SET price = p_new_price
        WHERE id = p_id;

        RAISE NOTICE 'Операция изменения цены выполнена';
    END IF;
END;
$$;
```

Проверим:

```
CALL update_product_price(1, 75000);
CALL update_product_price(1, -500);
```

Во втором случае цена не изменится.

## 11. Пополнение склада

Создадим процедуру `add_stock`, которая увеличивает количество товара.

```
CREATE PROCEDURE add_stock(
    p_id INTEGER,
    p_amount INTEGER
)
LANGUAGE plpgsql
AS $$
BEGIN
    IF p_amount <= 0 OR p_amount IS NULL THEN
        RAISE NOTICE 'Количество должно быть положительным';
    ELSE
        UPDATE products
        SET quantity = quantity + p_amount
        WHERE id = p_id;

        RAISE NOTICE 'Операция пополнения выполнена';
    END IF;
END;
$$;
```

```
CALL add_stock(1, 5);
```

Если было 5 ноутбуков, теперь будет 10.

Здесь студенты повторяют переменные, параметры, `IF` и `UPDATE`.

## 12. Продажа товара

Теперь более интересный пример: при продаже нужно проверить остаток и уменьшить количество товара.

```
CREATE PROCEDURE sell_product(
    p_id INTEGER,
    p_amount INTEGER
)
LANGUAGE plpgsql
AS $$
DECLARE
    current_quantity INTEGER;
BEGIN
    IF p_amount IS NULL OR p_amount <= 0 THEN
        RAISE NOTICE 'Некорректное количество';
        RETURN;
    END IF;

    SELECT quantity
    INTO current_quantity
    FROM products
    WHERE id = p_id
    FOR UPDATE;

    IF NOT FOUND THEN
        RAISE NOTICE 'Товар не найден';

    ELSIF current_quantity < p_amount THEN
        RAISE NOTICE 'Недостаточно товара на складе';

    ELSE
        UPDATE products
        SET quantity = quantity - p_amount
        WHERE id = p_id;

        RAISE NOTICE 'Продажа выполнена';
    END IF;
END;
$$;
```

Проверка:

```
CALL sell_product(1, 2);
CALL sell_product(1, 100);
CALL sell_product(999, 1);
```

`FOR UPDATE` блокирует выбранную строку до завершения транзакции, помогая избежать одновременной продажи одного и того же остатка. `FOUND` показывает, нашёл ли `SELECT INTO` строку.

`RETURN` без значения в процедуре завершает её выполнение досрочно.

# Часть IV. Управление процедурами

## 13. Изменение процедуры

Для изменения тела используем:

```
CREATE OR REPLACE PROCEDURE say_hello()
LANGUAGE plpgsql
AS $$
BEGIN
    RAISE NOTICE 'Добро пожаловать на занятие!';
END;
$$;
```

```
CALL say_hello();
```

## 14. Удаление процедуры

```
DROP PROCEDURE say_hello();
```

Если у процедуры есть параметры, можно указать их типы:

```
DROP PROCEDURE greet_user(TEXT);
```

## Задание 1. Вывод сообщения

## Задание 3. Изменение количества

Если количество отрицательное, выведите сообщение об ошибке через `RAISE NOTICE` и не изменяйте таблицу.

## Задание 4. Увеличение всех цен

Создайте процедуру `increase_all_prices(percent NUMERIC)`, которая увеличивает цены всех товаров на указанный процент.

Например:

```
CALL increase_all_prices(10);
```

Все цены должны увеличиться на 10%.

Если процент отрицательный, процедура не должна изменять данные.

## Задание 5. Удаление товаров без остатков

Создайте процедуру `delete_empty_products()`, которая удаляет товары, у которых `quantity = 0`.

## Задание 6. Продажа товара

Создайте процедуру `purchase_product`, которая принимает ID товара и количество для покупки.

Процедура должна:

1. Проверить существование товара.
2. Проверить, что количество покупки положительное.
3. Проверить достаточность остатка.
4. Уменьшить количество товара.
5. Вывести соответствующее сообщение.

## Задание 7. Скидка на выбранный товар

Создайте процедуру `apply_discount`, которая принимает ID товара и процент скидки.

Если скидка находится в диапазоне от 0 до 100, уменьшите цену товара. Иначе выведите сообщение о некорректной скидке.
