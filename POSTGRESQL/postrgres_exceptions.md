## Подготовка базы данных

Перед выполнением заданий создайте таблицы и добавьте готовые записи:

```sql
DROP TABLE IF EXISTS game_sales;
DROP TABLE IF EXISTS game_products;

CREATE TABLE game_products (
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name VARCHAR(100) NOT NULL UNIQUE,
    price NUMERIC(10, 2) NOT NULL CHECK (price > 0),
    quantity INTEGER NOT NULL CHECK (quantity >= 0)
);

CREATE TABLE game_sales (
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    product_id INTEGER REFERENCES game_products(id),
    quantity INTEGER NOT NULL CHECK (quantity > 0),
    total NUMERIC(10, 2) NOT NULL CHECK (total > 0),
    sold_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

INSERT INTO game_products (name, price, quantity)

    ('Уно', 500, 15),
    ('Дженга', 900, 10),

    ('Пазл', 1500, 2);
```

## Задание 1. Проверка цены товара

**Простое · 5 минут · `RAISE EXCEPTION`**

Сотрудник магазина иногда ошибается при вводе стоимости товара. Необходимо запретить использование нулевых и отрицательных цен.

Создайте функцию `validate_price()`:

- Принимает параметр `price NUMERIC`.
- Если цена больше нуля, возвращает её.
- Если цена меньше или равна нулю, вызывает `RAISE EXCEPTION` с сообщением «Цена должна быть больше нуля».

**Проверка:**

```sql
SELECT validate_price(1500);
SELECT validate_price(-500);
SELECT validate_price(0);
```

Ожидается: первый вызов возвращает `1500`, остальные вызывают ошибку.

## Задание 3. Безопасное деление чисел

**Простое · 7 минут · `EXCEPTION WHEN`**

Создайте функцию `safe_division()`:

- Принимает `a NUMERIC` и `b NUMERIC`.
- Возвращает результат деления.
- Перехватывает ошибку `division_by_zero` с помощью `EXCEPTION WHEN`.
- При ошибке выводит сообщение «Нельзя делить на ноль» и возвращает `NULL`.

**Проверка:**

```sql
SELECT safe_division(20, 4);
SELECT safe_division(15, 0);
SELECT safe_division(100, 5);
```

Ожидаемые результаты: `5`, `NULL`, `20`.

## Задание 4. Добавление товара без дубликатов

**Среднее · 10 минут · `unique_violation`**

Создайте процедуру `add_game()` с параметрами:

- `game_name VARCHAR(100)` — название;
- `game_price NUMERIC` — цена;
- `game_quantity INTEGER` — количество.

Процедура добавляет товар в `game_products`. При `unique_violation` она должна вывести «Товар с таким названием уже существует!». При успешном добавлении — «Товар успешно добавлен!».

**Проверка:**

```sql
CALL add_game('Каркассон', 2300, 7);
CALL add_game('Шахматы', 1500, 4);
```

Первый товар должен добавиться, второй — нет.

## Задание 5. Обработка некорректного количества

## Задание 8. Триггер для проверки скидки

**Среднее · 10 минут · Триггеры и исключения**

Создайте триггерную функцию `check_min_price()`:

- Функция возвращает `TRIGGER`.
- Проверяет `NEW.price`.
- Если новая цена меньше 100 рублей, вызывает `RAISE EXCEPTION 'Цена слишком низкая'`.
- Иначе возвращает `NEW`.
- Создайте триггер `min_price_trigger`, срабатывающий `BEFORE UPDATE OF price` для каждой строки `game_products`.

**Проверка:**

```sql
UPDATE game_products
SET price = 50
WHERE id = 1;
```

Должна возникнуть ошибка; цена не изменится.

```sql
UPDATE game_products
SET price = 1100
WHERE id = 1;
```

Изменение должно пройти успешно.
