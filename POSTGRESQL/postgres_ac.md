# Практическая работа «Пользователи, роли и права доступа в PostgreSQL»

## 1. Описание проекта

В магазине GameBox используется единая база данных, в которой хранятся товары и продажи. С ней работают три категории сотрудников:

| Сотрудник | Обязанности |
|---|---|
| Менеджер | Добавление и изменение товаров |
| Продавец | Просмотр товаров и оформление продаж |
| Аналитик | Просмотр товаров и анализ продаж |

Необходимо настроить систему доступа так, чтобы каждый сотрудник мог выполнять только разрешённые ему операции.

## 2. Подготовка базы данных

Перед выполнением заданий запустите следующий SQL-скрипт от имени администратора или владельца объектов.

```sql
CREATE SCHEMA IF NOT EXISTS gamebox_lab;

CREATE TABLE IF NOT EXISTS gamebox_lab.products (
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name VARCHAR(100) NOT NULL UNIQUE,
    price NUMERIC(10, 2) NOT NULL CHECK (price > 0),
    quantity INTEGER NOT NULL CHECK (quantity >= 0)
);

CREATE TABLE IF NOT EXISTS gamebox_lab.sales (
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    product_id INTEGER REFERENCES gamebox_lab.products(id),
    quantity INTEGER NOT NULL CHECK (quantity > 0),
    total NUMERIC(10, 2) NOT NULL CHECK (total > 0),
    sold_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

INSERT INTO gamebox_lab.products (name, price, quantity)
VALUES
    ('Шахматы', 1200, 8),
    ('Монополия', 2500, 5),
    ('Уно', 500, 15),
    ('Дженга', 900, 10),
    ('Мафия', 700, 12),
    ('Пазл', 1500, 4)
ON CONFLICT (name) DO NOTHING;
```

Проверьте созданные таблицы:

```sql
SELECT * FROM gamebox_lab.products;
SELECT * FROM gamebox_lab.sales;
```

Все дальнейшие задания выполняются с этими таблицами.

> **Важно:** для создания ролей нужны административные полномочия, а для выдачи прав на таблицы — соответствующие полномочия владельца или право предоставлять привилегии. Если студенты работают на общем сервере, преподавателю необходимо подготовить необходимые полномочия и отдельные имена ролей для каждого студента.

## Задание 1. Создание пользователей магазина

**Время:** 7 минут  
**Тема:** `CREATE ROLE`, `CREATE USER`

В магазине работают три сотрудника: менеджер, продавец и аналитик. Создайте для каждого отдельную учётную запись PostgreSQL.

| Пользователь | Имя роли |
|---|---|
| Менеджер | `gb_manager` |
| Продавец | `gb_seller` |
| Аналитик | `gb_analyst` |

**Требования:**

1. Использовать `CREATE ROLE` или `CREATE USER`.
2. Разрешить всем трём пользователям подключаться к серверу с помощью `LOGIN`.
3. Установить каждому отдельный пароль.
4. Не предоставлять права `SUPERUSER`.

После создания проверьте существование пользователей запросом к `pg_roles`.

**Ожидаемый результат:** в PostgreSQL созданы три роли с возможностью подключения.

## Задание 2. Просмотр и изменение ролей

**Время:** 6 минут  
**Тема:** `pg_roles`, `ALTER ROLE`

Администратор хочет проверить настройки пользователей.

**Выполните:**

1. Выведите список созданных ролей.
2. Определите, какие роли имеют атрибут `LOGIN`.
3. Проверьте, что ни одна из созданных ролей не является суперпользователем.
4. Измените пароль пользователя `gb_seller` с помощью `ALTER ROLE`.
5. Временно отключите возможность подключения для `gb_analyst` через `NOLOGIN`.
6. Верните возможность подключения через `LOGIN`.

Для проверки используйте системное представление:

```sql
SELECT rolname, rolcanlogin, rolsuper
FROM pg_roles
WHERE rolname LIKE 'gb_%';
```

**Ожидаемый результат:** студент умеет просматривать атрибуты ролей и изменять их.

## Задание 3. Предоставление прав менеджеру

**Время:** 8 минут  
**Тема:** `GRANT`

Менеджер отвечает за ассортимент магазина. Ему необходимо разрешить:

- Просматривать товары (`SELECT`).
- Добавлять новые товары (`INSERT`).
- Изменять информацию о товарах (`UPDATE`).

Удалять товары менеджеру запрещено.

**Выполните:**

1. Предоставьте `gb_manager` право `USAGE` на схему `gamebox_lab`.
2. Предоставьте необходимые права на таблицу `gamebox_lab.products` с помощью `GRANT`.
3. Подключитесь к базе данных от имени менеджера.
4. Попробуйте добавить товар «Каркассон» стоимостью 2200 рублей.
5. Измените цену «Каркассона» на 2500 рублей.
6. Попробуйте удалить этот товар.

Для проверки:

```sql
INSERT INTO gamebox_lab.products (name, price, quantity)
VALUES ('Каркассон', 2200, 5);

UPDATE gamebox_lab.products
SET price = 2500
WHERE name = 'Каркассон';

DELETE FROM gamebox_lab.products
WHERE name = 'Каркассон';
```

**Ожидаемый результат:** первые две операции выполняются успешно, а удаление завершается ошибкой доступа.

## Задание 4. Настройка прав продавца

**Время:** 8 минут  
**Тема:** `GRANT SELECT`, `GRANT INSERT`

Продавец должен просматривать каталог и оформлять продажи.

Ему разрешено:

- Читать таблицу `products`.
- Читать таблицу `sales`.
- Добавлять записи в таблицу `sales`.

Ему запрещено изменять цены товаров и удалять продажи.

**Выполните:**

1. Предоставьте `gb_seller` право `USAGE` на схему.
2. Настройте разрешённые операции для обеих таблиц.
3. Подключитесь от имени продавца.
4. Выведите список товаров.
5. Добавьте продажу одной игры «Уно».
6. Попробуйте изменить цену «Шахмат».
7. Попробуйте удалить запись из `sales`.

Пример добавления продажи:

```sql
INSERT INTO gamebox_lab.sales (
    product_id,
    quantity,
    total
)
SELECT id, 1, price
FROM gamebox_lab.products
WHERE name = 'Уно';
```

**Ожидаемый результат:** просмотр и добавление продажи разрешены, изменение цены и удаление продажи запрещены.

*В рамках этого задания продажа является записью в таблице. Уменьшение складского остатка здесь не реализуется.*

## Задание 5. Настройка доступа аналитика

**Время:** 7 минут  
**Тема:** `GRANT SELECT`

Аналитик составляет отчёты о товарах и продажах. Ему необходимо разрешить только чтение данных.

**Выполните:**

1. Предоставьте `gb_analyst` право `USAGE` на схему.
2. Предоставьте право `SELECT` на таблицы `products` и `sales`.
3. Подключитесь от имени аналитика.
4. Получите список всех товаров.
5. Посчитайте общую сумму продаж.
6. Попробуйте добавить новый товар.
7. Попробуйте изменить количество товара.

Запрос для анализа продаж:

```sql
SELECT
    COUNT(*) AS sales_count,
    COALESCE(SUM(total), 0) AS total_revenue
FROM gamebox_lab.sales;
```

**Ожидаемый результат:** аналитические запросы выполняются, а операции изменения данных запрещены.

## Задание 7. Создание групповой роли

**Время:** 9 минут  
**Тема:** `NOLOGIN`, `GRANT ROLE`

В магазин планируют нанять нескольких аналитиков. Чтобы не назначать каждому одинаковые права отдельно, необходимо создать общую роль.

**Выполните:**

1. Создайте роль `gb_readonly` с атрибутом `NOLOGIN`.
2. Предоставьте ей `USAGE` на схему `gamebox_lab`.
3. Предоставьте ей `SELECT` на таблицы `products` и `sales`.
4. Отзовите ранее выданные напрямую права `SELECT` у `gb_analyst`.
5. Добавьте `gb_analyst` в группу `gb_readonly`.
6. Проверьте, что аналитик по-прежнему может читать данные.

**Ожидаемый результат:** аналитик получает права через членство в групповой роли.

## Задание 8. Проверка назначенных привилегий

**Время:** 8 минут  
**Тема:** `has_table_privilege()`

Администратору необходимо проверить, правильно ли настроены разрешения. Используйте функцию PostgreSQL `has_table_privilege()`.

Пример:

```sql
SELECT has_table_privilege(
    'gb_analyst',
    'gamebox_lab.products',
    'SELECT'
);
```

Функция возвращает `true`, если у роли есть указанная привилегия, и `false`, если её нет.

**Проверьте:**

1. Может ли менеджер читать таблицу товаров?
2. Может ли менеджер удалять товары?
3. Может ли продавец добавлять продажи?
4. Может ли продавец изменять цены?
5. Может ли аналитик читать таблицу продаж?
6. Может ли аналитик добавлять товары?

Результаты оформите в таблицу:

| Пользователь | Таблица | Операция | Результат |
|---|---|---|---|
| `gb_manager` | `products` | `SELECT` | |
| `gb_manager` | `products` | `DELETE` | |
| `gb_seller` | `sales` | `INSERT` | |
| `gb_seller` | `products` | `UPDATE` | |
| `gb_analyst` | `sales` | `SELECT` | |
| `gb_analyst` | `products` | `INSERT` | |

## 3. Требования к сдаче практической работы

Студент должен представить один SQL-файл, содержащий команды для выполнения всех заданий.

В файле необходимо:

- Разделить задания комментариями `-- Задание 1`, `-- Задание 2` и т. д.
- Сохранить команды создания ролей, назначения и отзыва привилегий.
- Добавить запросы для проверки предоставленных прав.
- Указать в комментариях ожидаемый результат запрещённых операций.
- Не включать реальные пароли учётных записей в сдаваемый файл.

Проверки от имени разных пользователей выполняются через отдельные подключения. Ошибочные запросы следует запускать отдельно, чтобы они не мешали выполнению остальных команд.
